# Screener

Сканер читает сохранённую таблицу Coinalyze **Perpetual** через браузер Playwright, рассчитывает рыночные метрики и сценарии, получает закрытые свечи и стакан Binance Futures и отправляет наблюдения в Telegram. Торговые ордера не выставляются.

## Запуск

Проект рассчитан на GitHub Actions. Внешний Cron-сервис должен вызывать workflow через `repository_dispatch` с типом события `run_screener` либо запускать его вручную через `workflow_dispatch`. Расписание внутри GitHub Actions намеренно не задано.

Для ручного запуска `dry_run` по умолчанию включён. Для `repository_dispatch` включена реальная отправка Telegram.

## GitHub Secrets

Помимо перечисленных в репозитории секретов, для чтения закрытой/сессионной таблицы Coinalyze нужны ещё три секрета:

| Secret | Значение |
|---|---|
| `COINALYZE_URL` | Полная сохранённая HTTPS-ссылка Coinalyze с `contract_type=perpetual` и нужными фильтрами/колонками |
| `COINALYZE_P_SID` | Значение cookie `p_sid` |
| `COINALYZE_CHAT_SID` | Значение cookie `chat_sid` |
| `TG_BOT_TOKEN` | Токен Telegram-бота |
| `TG_CHAT_IDS` | Один или несколько chat ID через запятую |
| `WIREGUARD_CONF` | Полный конфиг WireGuard для Binance-прокси |

`BINANCE_API_KEY` в текущем коде не используется: свечи, exchangeInfo и стакан запрашиваются с публичных Binance Futures endpoints. Не передавайте API-ключ с торговыми правами; для этого проекта он не нужен.

## История и хранение

История хранится в `data/` в четырёх JSONL-файлах: `snapshots.jsonl`, `market_rows.jsonl`, `notifications.jsonl`, `runs.jsonl`. GitHub Actions коммитит изменения этих файлов **в ту же ветку, из которой запущен workflow**. Отдельная ветка `screener-state` не используется. Поэтому в настройках репозитория должен быть разрешён `GITHUB_TOKEN` с `contents: write`, а правила защиты ветки не должны запрещать этому токену push.

Это означает, что история будет видна в обычной истории коммитов основной/рабочей ветки и увеличит размер репозитория. Если ветка защищена от прямых push, сохранение завершится ошибкой; в таком случае нужен внешний storage или отдельная state-ветка. Не удаляйте `data/*.jsonl`, если хотите сохранить историю.

Сроки хранения: рыночные снимки — 30 дней, история запусков — 90 дней, журнал уведомлений — 180 дней. Очистка выполняется при запуске.

## Важные ограничения

- Coinalyze API не используется: данные извлекаются из HTML-таблицы браузером. Изменение HTML, названий колонок, cookies или пагинации может остановить сбор; при неполной таблице анализ и уведомления блокируются.
- Исторические JSONL-файлы сохраняют таблицу Coinalyze. Свечи и стакан Binance запрашиваются заново при каждом запуске и в историю не записываются.
- Частота запуска определяет качество исторических сравнений. Для 4H-последовательностей нужен интервал около 4 часов; более частые запуски не являются независимыми 4H наблюдениями.
- Уведомления — аналитические наблюдения, не торговые рекомендации и не автоматические входы.

## Локальная проверка

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

Секреты задаются только в GitHub Actions; `.env` и `.env.example` не используются.
